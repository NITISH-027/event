DATABASE SCHEMA
---------------
Three core tables with complete RLS policies:

1. profiles - User metadata and institutional information
   - id (UUID, primary key, references auth.users)
   - email, full_name, institution, avatar_url
   - Timestamps: created_at, updated_at

2. events - Event details with ownership tracking
   - id (UUID, primary key)
   - title, description, event_date, event_time, location
   - category, image_url, institution
   - created_by (foreign key to profiles)
   - Timestamps: created_at, updated_at

3. comments - User engagement on events
   - id (UUID, primary key)
   - event_id (foreign key to events, cascade delete)
   - user_id (foreign key to profiles)
   - content
   - Timestamps: created_at, updated_at

Performance indexes on:
- events: created_by, institution, category, event_date
- comments: event_id, user_id

SECURITY MODEL
--------------
Multi-layered security approach:

1. Authentication Layer
   - Supabase Auth with session tokens
   - Secure password hashing
   - Protected route components

2. Authorization Layer  
   - Row-Level Security: auth.uid() = created_by
   - Ownership verification before modifications
   - Type-safe database queries

3. Storage Security
   - Authenticated upload only
   - Public read access for visibility
   - User-specific folder structure

4. Data Validation
   - Client-side form validation
   - Required field enforcement
   - TypeScript type checking
